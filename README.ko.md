# OpenDIY Desktop

**빠른 로딩, 실제 사용 화면**

기존 ChatGPT 데스크톱 앱보다 빠른 로딩을 체감한 실사용 녹화입니다.
프로젝트를 전환하며 여러 실행 중 세션이 표시되는 모습을 약 6.5초 동안 확인할 수 있습니다.

*같은 실사용 환경의 작업 관리자입니다. OpenDIY Desktop과 CLI·WebView2 프로세스가 함께 실행 중인 상태입니다.*

[English](README.md) | **한국어**

여러 코딩 에이전트 CLI 세션을 한 화면에 배치하는 Windows 데스크톱 앱입니다.
Codex 실행 기반은 [OpenDIY Codex](https://github.com/jaeseongs95/opendiy-codex)이며,
호환되는 공식 Codex CLI도 지원합니다. 터미널 격자의 크기와 순서를 바꾸고,
프로젝트별로 세션을 보거나 터미널 출력을 검색할 수 있습니다.
입력은 각 터미널에서 직접 보냅니다.

![이전 Agent Grid 이름의 디자인 미리보기](docs/design-demo.png)

*정적인 터미널 예시를 사용한 디자인 데모이며, 실제 실행 검증 자료가 아닙니다.*

독립적으로 구현한 MIT 프로젝트입니다. Claudes의 코드·이미지·브랜딩을 포함하지
않습니다. 다중 터미널 작업 흐름을 제품 참고 자료로 사용했으며, 해당 프로젝트의
소스 공개 라이선스는 승인 없는 수정·재배포를 허용하지 않습니다.
[참고 프로젝트 라이선스](https://github.com/paulallington/Claudes/blob/v1.9.82/LICENSE)를
확인할 수 있습니다.

## 언어 선택

오른쪽 위 **⚙ 설정**을 열고 **언어**에서 **한국어** 또는 **English**를 선택하세요.
앱 화면과 앱이 지정하는 트레이·선택창 안내에 즉시 반영되며, 다음 실행에도 유지됩니다.
데스크톱 앱의 언어 선택값은 앱 자체 SQLite 설정에 저장하며 기본 언어는 한국어입니다.
세션 이름·경로·대화 내용·터미널 출력은 원문 그대로 표시합니다.
CLI 진단 메시지나 Windows 기본 버튼은 원래 언어로 표시될 수 있습니다.
CLI와 운영체제의 언어 설정은 바꾸지 않습니다.

## 실행

[Releases](https://github.com/jaeseongs95/opendiy-desktop/releases)에서 포터블 ZIP이나
사용자 단위 설치 파일을 내려받으세요. Windows x64와 WebView2가 필요하며,
실행 파일은 서명되지 않았습니다.
포터블 ZIP 전체를 압축 해제한 뒤 `opendiy-desktop.exe`를 실행하세요.
`opendiy-desktop-helper.exe`는 같은 폴더에 두어야 합니다. Windows 터미널 처리는
콘솔용 보조 프로세스가 담당하고, 메인 앱은 일반 데스크톱 창으로 실행됩니다.

먼저 OpenDIY Codex 또는 호환되는 공식 Codex CLI를 별도로 설치하고 로그인하세요.
데스크톱 배포물에는 CLI 실행 파일이 없으며 앱이 이를 내려받지도 않습니다. 오른쪽 위
**⚙ 설정 → 실행 파일 설정**에서 네이티브 `codex.exe`를 선택하면
새 세션과 세션 조회에 사용할 경로가 저장됩니다.
저장한 경로·실제 적용 경로·찾은 위치를 확인할 수 있습니다.
파일 선택을 취소하면 기존 설정을 유지하고, 경로를 바꿔도 열린 터미널은 유지합니다.

**자동 찾기**는 앱에 저장한 경로를 지우고 `AGENT_GRID_CODEX` 환경변수,
`PATH` 순서로 실행 파일을 찾습니다. 직접 저장한 경로가 가장 우선합니다.
경로가 잘못되면 오류를 표시하며 다른 실행 파일로 몰래 대체하지 않습니다.
CLI는 `--remote`와 공유 서버·프록시 명령 또는 인증된 app-server WebSocket을 지원해야 합니다.
공유 연결을 지원하는 CLI에서 접속에 실패하면 원인을 표시하며 개별 서버로 몰래 대체하지 않습니다.

**프로젝트 가져오기**에서 Windows 기본 폴더 선택창(`IFileOpenDialog`)으로 기존 로컬
폴더를 선택하세요. 가져온 프로젝트는 터미널이 종료되어도 사이드바에 남습니다.
해당 프로젝트의 세션 불러오기 팝업에서 기존 대화를 선택하거나,
작업 경로가 채워진 새 세션을 시작할 수 있습니다.

**새 프로젝트**는 이름을 가진 세션 묶음을 만들며, 기존 기본 실행 폴더는 선택 사항입니다.
디스크에 새 폴더를 만들지는 않습니다. 프로젝트 옆 **⋯**에서 이름을 바꾸거나
즐겨찾기로 지정하고 삭제할 수 있습니다. 삭제는 앱의 프로젝트 메타데이터만 지우고
소속 세션을 **미분류**로 옮깁니다. 실행 중인 터미널·원본 대화·디스크 폴더는 보존합니다.
세션의 **프로젝트로 이동**도 소속만 바꾸며 터미널을 다시 시작하거나 실제 실행 폴더를
바꾸지 않습니다.

격자 위 프로젝트 탭이나 사이드바에서 프로젝트를 선택하면 해당 프로젝트의
열린 세션을 볼 수 있습니다. **전체**는 모든 세션을 표시합니다.
탭을 전환해도 터미널 실행과 출력을 유지하며, 프로젝트 전환이나 세션 이동 뒤에는
최신 출력 위치를 표시합니다. 세션 이동 단축키는 현재 보이는 프로젝트에
적용됩니다. 선택한 프로젝트에 기본 폴더가 있으면
새 세션·세션 불러오기도 그 경로에서 시작합니다.

**세션 불러오기**는 좌우로 나뉜 팝업입니다. 왼쪽에서 제목을 검색하고 프로젝트로
필터링한 뒤, 오른쪽에서 날짜·대화 ID·최근 대화를 확인하세요.
이미 열린 대화는 기존 터미널로 이동합니다. 조회할 때만 앱 소유 서버를 잠시
사용하므로 기존 데스크톱 데몬이 필요하지 않습니다.
최근 대화는 정해진 크기로 나눠 읽으며 앱 데이터베이스에 복사하지 않습니다.

**새 세션**에서는 경로를 직접 입력할 수도 있습니다. 모델 선택·로그인·권한 응답은
공식 CLI 화면에서 처리하세요. 제어할 터미널에 직접 입력하세요.
CLI 입력창에서 **Shift+Enter**로 줄바꿈할 수 있습니다.

## 앱 재시작과 세션 복원

앱을 완전히 종료했다가 다시 실행하면 종료 직전에 열려 있던 작업 공간을 복원합니다.
실행 중이던 세션은 저장된 대화 ID로 다시 연결하며 제목·프로젝트·격자 순서와 크기를
유지합니다. 이전 입력을 다시 보내거나 저장된 터미널 대화록 전체를 적재하지 않습니다.
개별로 닫은 세션은 다시 열지 않습니다.

대화 ID가 없거나 이미 종료한 세션, 이전 버전에서 실행 의도 없이 저장한 항목은
자동으로 새 대화를 만들지 않습니다. 연결하지 못한 항목은 저장된 세션 목록에 남아
직접 다시 시도할 수 있습니다. 일부 연결이 실패해도 나머지 저장 항목을 지우지 않습니다.
창의 닫기 버튼으로 트레이에 숨겼다가 다시 여는 경우에는 실행 중인 터미널을 그대로 사용합니다.

실행하지 않는 저장 항목은 동시 실행 개수에 포함하지 않습니다. 실제 터미널은 기존
32개 자원 상한을 유지하며, 자동 복원이 이 상한에 도달하면 남은 항목은 저장 목록에 둡니다.

## 서브에이전트 조회·관리

실행 중인 세션 상단의 **서브에이전트 관리** 아이콘에서 해당 세션의 직접 하위
에이전트를 확인합니다. 왼쪽에서 현재 페이지를 검색하고, 오른쪽에서 상태·역할·모델·
추론 수준을 확인한 뒤 지시 전송·현재 작업 중단·종료·재개를 요청할 수 있습니다.
종료는 하위 작업도 중단하므로 한 번 더 확인하며 저장된 대화는 삭제하지 않습니다.

이 기능에는 `supportsSubagentManagement`를 알리는 호환 CLI가 필요합니다.
미지원 실행 파일에서는 관리 요청을 보내지 않습니다. 목록은 한 번에 100개씩 조회하고
팝업이 보일 때만 5초 간격으로 갱신하며 대화 본문은 가져오지 않습니다. 응답이 유실된
변경은 자동 재전송하지 않고 원래 요청의 처리 여부를 다시 확인합니다.

선택한 CLI가 최신이어도 이미 실행 중인 공유 서버가 이 기능을 지원하지 않으면 사용할 수
없습니다. 실행 파일을 선택하거나 앱만 다시 시작해도 그 서버는 업데이트되지 않습니다.
서버 갱신은 진행 중인 작업을 중단할 수 있으므로 작업을 마친 뒤 호환 배포물의 갱신 절차를
따르세요. 앱은 이 작업을 자동으로 실행하지 않습니다.

## 플러그인과 스킬

오른쪽 위 **⚙ 설정 → 플러그인·스킬**을 열면 실행 파일 설정에서 선택한 CLI와 현재 프로젝트를
기준으로 관리합니다. 설치됨·설치 가능 플러그인과 스킬을 검색하고, 플러그인 설치·제거·
활성화, 마켓플레이스 소스 관리, 스킬 활성화를 수행할 수 있습니다. `SKILL.md`가 들어 있는
로컬 스킬 폴더를 Windows 기본 폴더 선택창으로 골라 현재 프로젝트나 사용자 스킬
폴더로 가져올 수 있습니다.
적용 전 검토 화면에서 실제 대상과 범위를 확인합니다. 기존 폴더를 덮어쓰지 않으며,
링크나 크기 제한을 넘는 폴더는 거부합니다. CLI가 지원하지 않는 기능과 오류도 표시합니다.

플러그인·마켓플레이스는 CLI 명령으로, 스킬·설정은 app-server API로 실제 반영하고
결과를 다시 조회합니다. CLI 인증과 설정은 해당 CLI가 관리합니다. 변경된 확장 기능은
새 세션에서 사용하며, 실행 중인 터미널을 강제로 재시작하지 않습니다.

## 모바일 원격 제어

오른쪽 위 **⚙ 설정 → 모바일 원격 제어**에서 실행 중인 세션을 선택하고 상태를 조회하세요.
원격 제어를 켜고 상태를 새로고침해 원격 서비스 연결을 확인한 뒤,
연결 코드를 만들어 모바일 Codex에 입력합니다. 원격 서비스 연결됨은 세션 서버가
중계 서비스에 연결됐다는 뜻이며, 실제 휴대전화 연결 여부와는 별개입니다.

선택한 CLI는 원격 제어 app-server API를 지원하며 ChatGPT 계정으로 로그인해야 합니다.
API 키 로그인은 지원하지 않습니다. 공유 서버를 지원하는 CLI에서는 기본 프록시를 통해
터미널·상태 관측·모바일 관리가 같은 기존 서버에 연결됩니다. 켜기·끄기와 연결 코드는
그 서버의 모든 대화에 적용됩니다. 앱 시작 시 실행 중인 공유 서버를 재사용하거나
설치된 서버를 먼저 시작하고, 연결을 확인한 뒤 세션을 복원합니다. 시작에 실패하면
저장된 세션을 유지하며 다시 시도할 수 있습니다. 공유 서버를 설치·교체·종료하지는 않습니다.
자동 시작에는 CLI의 `app-server daemon start --existing-installation` 옵션이 필요합니다.
이 옵션이 없는 구형 CLI는 공유 서버를 먼저 실행한 뒤 앱을 열어야 합니다.

공유 명령이 없는 구형 CLI는 앱 소유의 개별 서버를 유지합니다. 이 경로의 모바일 변경에는
기존 원격 등록을 보호하기 위한 `--remote-control-client-name` 지원이 필요합니다.
상태 응답에서 변경 가능 여부를 확인할 때까지 버튼을 비활성화하고 연결 범위를 표시합니다.

공유 세션 종료는 터미널을 닫기 전에 원래 작업 ID를 고정해 그 작업만 중단합니다.
늦게 시작한 모바일 작업으로 대상을 바꾸지 않습니다. 중단 결과가 불명이면 알 수 없음으로
남기고 자동 재전송하지 않습니다. 앱을 종료해도 공유 서버와 기존 원격 등록은 유지됩니다.
일반 종료가 중단 미확인으로 실패해도 로컬 자원이 모두 회수됐다면, 경고를 확인한 뒤
**중단 미확인 상태로 앱 닫기**를 따로 선택할 수 있습니다. 원격 작업이 계속 실행될 수 있으며,
이 선택은 작업 상태를 중단됨으로 바꾸거나 중단 요청을 다시 보내지 않습니다.
연결 코드는 저장하지 않으며 실제 휴대전화 연결과 제어는 아직 검증하지 않았습니다.
공유 연결에는 새 빈 대화 재개와 기본 프록시 보호 경계가 수정된 CLI가 필요합니다.
원본 R28에는 원격 API가 있지만 이 수정은 포함되지 않았습니다. 호환 실행 파일과 체크섬은
릴리스 노트에서 확인하세요. 초기 이력을 아직 조회할 수 없다는 경고가 있어도 살아 있는
세션의 입력은 유지됩니다. 이 경고를 과거 대화 전체가 불러와졌다는 뜻으로 해석하지 마세요.

## 주간 사용량

왼쪽 아래 표시기는 선택한 CLI 계정의 대표 사용 한도 중 기간이 명시적으로 10,080분인
주간 구간에서 사용 비율과 제공되는 초기화 시각을 읽습니다. 이 앱의 세션 사용량을
합산한 값이 아닌 계정 사용량입니다. 주간 정보 미제공과 조회 실패를 구분하며
0%로 처리하지 않습니다. 이전 조회가 끝난 뒤 1분마다 자동으로 조회하며, 창이 숨겨진
동안에는 멈춥니다. 새로고침 버튼으로 즉시 다시 조회할 수 있고, 수동 조회는 5초 간격으로
한 번에 하나씩 실행합니다. 실패하면 마지막 정상값과 조회 시각을 유지하며 기술 오류는
사용량 화면에 표시하지 않습니다. 외부 세션 기록은 설정에서 확인할 수 있습니다.

## 메모리와 대화 조회

필요할 때만 세션·대화를 한 페이지에 최대 50개씩 조회합니다. 화면에는 세션 목록 250개,
미리보기 메시지 100개·텍스트 128 KiB까지 유지하며, 더 불러오면 오래된 표시 페이지부터
비웁니다. 같은 세션을 다시 선택하면 최근 대화로 돌아갑니다. 팝업을 닫을 때 행·미리보기·
선택 정보를 해제하며, 대화 본문을 앱 데이터베이스에 복사하지 않습니다.
확장 관리 팝업도 처음에 50개 행을 표시하고, 닫을 때 조회한 데이터를 해제합니다.
터미널 입력은 처리 중인 요청을 포함해 최대 128개·256 KiB를 허용하며, 요청 하나의
크기는 기존 네이티브 제한인 64 KiB를 따릅니다. 대기량이 많으면 입력을 잠시 막고,
초과 입력은 알립니다. 크기 변경은 처리 중인 요청 하나와 최신 대기 크기만 유지합니다.
터미널 제거 시 대기 중인 입력·크기 참조를 해제하고, 저장된 세션은 처음에 메타데이터만 읽습니다.
OpenDIY Codex R28은 표시 이력에도 30턴·400항목·논리적 원자료 8 MiB 예산을 적용합니다.
과거 구간은 필요할 때 조회하며, 독립 작업이 끝나면 멀어진 표시 참조를 해제합니다.
이는 프로세스 전체·대화 원본·모델 문맥의 메모리 상한이 아닙니다. 구형 이력은 공식 전체
읽기 경로를 사용하므로 처음 불러올 때는 표시 예산을 넘을 수 있습니다. 다른 CLI를
선택하면 해당 CLI의 이력 처리 방식을 따릅니다.
상한과 객체 해제 시험을 장시간 메모리 누수 시험 완료로 표현하지 않습니다.
서버 요청의 응답·해결 기록은 세션마다 1,024개까지 보존합니다. 상한을 넘는 기록이
생기면 대화 관측과 입력 인계를 제한합니다. 해결된 질문이 늦은 알림으로 되살아나는
것을 막기 위한 제한이며, 원래 작업이나 대화 원본을 삭제하지 않습니다.

이전 Agent Grid의 설정과 등록 프로젝트는 유지합니다. Codex 실행 기반은
[OpenDIY Codex](https://github.com/jaeseongs95/opendiy-codex)이며, 호환되는 공식 CLI도
선택할 수 있습니다. 장기적으로 ChatGPT·Claude 데스크톱 앱의 기능과 사용성을 참고하되,
전체 벤치마킹과 더 넓은 기능 이전은 이후 작업입니다.

## 개발

Windows에서 Node.js 24, Rust stable, MSVC 빌드 도구와 WebView2가 필요합니다.

```powershell
npm ci
npm test
npm run build
node scripts/notices.mjs
cargo test --locked --manifest-path src-tauri/Cargo.toml
npm run tauri -- dev
```

콘솔 보조 실행 파일을 먼저 빌드한 뒤 데스크톱 앱을 패키징합니다.

```powershell
cargo build --locked --manifest-path src-tauri/Cargo.toml --release --bin opendiy-desktop-helper
npm run tauri -- build --config src-tauri/tauri.bundle.conf.json --bundles nsis
```

한글 경로로 네이티브 도구에 문제가 생기면 `D:/codex/build/opendiy-desktop` 아래의
별도 체크아웃에서 빌드하세요. 네이티브 빌드 전에 생성한 외부 라이선스 고지는
설치 파일과 포터블 실행 파일에 함께 배포합니다.

## Codex와 데이터

기존 로그인과 `CODEX_HOME`을 사용합니다. CLI를 설치·업데이트하거나
전역 권한 설정을 바꾸지 않습니다. 모델 선택은 Codex의 `/model`에서 합니다.
관리 세션은 명시적인 대화 ID를 지정한 일반 Codex 터미널을 사용합니다. 공유 서버를
지원하는 CLI는 기존 서버에 연결하고, 구형 CLI는 앱 소유의 인증된 loopback 서버를
사용합니다. 외부 세션은 공식 프록시로 읽기 전용 관측합니다. 공유 서버 접속 실패나
미확인 상태를 명시하며 다른 서버를 자동으로 시작하지 않습니다.

창 닫기는 트레이로 숨기고, 앱 종료는 확인 후 앱이 소유한 프로세스를 종료합니다.
완전히 종료한 뒤 복원하면 저장한 대화 ID로 새 프로세스를 시작합니다.
앱 자체 SQLite에는 레이아웃·세션 메타데이터·프로젝트·실행 파일 선택을 저장합니다.
인증 토큰·터미널 대화록·Codex 인증 파일은 복사하지 않습니다.
언어 선택도 앱 자체 SQLite 설정에 저장하며 브라우저 미리보기만 localStorage를 사용합니다.

## 검증과 릴리스

Windows CI에서 프런트엔드 검사·Rust 시험·패키징을 실행합니다.
릴리스에는 서명되지 않은 Windows x64 포터블 ZIP, NSIS 설치 파일과 SHA-256
검증값이 포함됩니다. 서명이 없어 Windows 실행 경고가 나타날 수 있습니다.
실제 검증 결과와 남은 한계는 각 릴리스 노트를 확인하세요.
빌드 성공만으로 장시간 안정성이나 모든 CLI 버전의 호환성을 보장하지 않습니다.

패키지 실행 파일의 진단 모드는 다음과 같습니다.

```powershell
opendiy-desktop.exe --self-test --duration-seconds 60 --report D:/codex/build/pty-result.json
opendiy-desktop.exe --codex-smoke --sessions 2 --cwd D:/projects/already-trusted --report D:/codex/build/codex-result.json
```

첫 모드는 로컬 셸로 실제 PTY를 사용해 2/8/16개 격리·오래된 세대 거부·출력 제한·취소·
100회 생성/종료와 8개 PTY 지속 동작을 검사합니다.
`--duration-seconds 14400`으로 지속 구간을 4시간으로 지정할 수 있습니다.
두 번째 모드는 모델 요청이나 권한 승인을 보내지 않고 실제 Codex 서버와 원격 TUI를 시작합니다.
`--cwd`에는 기존에 신뢰한 폴더를 지정하고, 결과 경로는 그 프로젝트 밖에 두세요.
시작 문맥을 읽지만 프로젝트 파일은 쓰지 않습니다.
`--cwd`를 생략하면 결과 경로 옆에 새 폴더를 만들며 정상적인 신뢰 확인 화면에서 멈출 수 있습니다.
스레드 ID와 실행 상태를 관측하고, 원문 대화 대신 터미널 해시를 기록합니다.
두 진단 모드 모두 물리적인 IME나 GUI 조작 검증을 대신하지 않습니다.

## 대화 보기와 질문함

세션 카드의 **대화 / 터미널** 버튼으로 같은 대화의 보기를 전환합니다. 기존 터미널 격자는
유지되며, 보기 전환으로 새 대화를 만들거나 이전 입력을 다시 보내지 않습니다. 대화
보기는 실행 기반의 구조화된 이력을 페이지로 읽고 최근 이벤트를 반영합니다. 오래된
구간과 큰 원문은 필요할 때 조회하며 터미널 문자열을 메시지로 변환하지 않습니다.

대화 보기에는 수동 구독과 유휴 상태 입력을 지원하는 실행 기반이 필요합니다.
새 실행 파일을 선택해도 이미 실행 중인 공유 서버의 버전이 자동으로 바뀌지는 않습니다.
대화 보기는 실제 연결한 서버의 지원 여부를 확인하며, 앱이 기존 서버를 중단하거나 교체하지 않습니다.
구형 서버에서는 기능 제한을 안내하며, 보기 전환으로 대기 작업을 실행하거나 진행 중인
작업에 새 입력을 합칠 수 있는 이전 방식으로 대체하지 않습니다. 기존 터미널 보기는
유지됩니다. 주간 사용량도 기존 공유 서버로만 조회하며, 서버를 사용할 수 없으면
마지막으로 확인한 값과 조회 시각을 유지합니다.

작성창은 여러 줄과 한글 조합, 이미지 붙여넣기, 파일 선택을 지원합니다. 일반 파일은
로컬 파일 참조이며 ChatGPT의 문서 업로드 서비스와 동일한 기능이 아닙니다. 모델과
추론 수준은 실행 기반이 알려준 값과 선택 가능한 목록을 사용합니다. 확인하지 못한
값은 미확인으로 표시합니다. 실행 기반이 지원하지 않는 기능은 오류나 제한으로 표시합니다.
전송 결과가 불명확하면 자동으로 다시 보내지 않고 초안을 보존합니다.
터미널로 돌아가려는 명시적인 전환은 일반 미응답 요청을 남긴 채 입력을 인계할 수 있습니다.
응답 처리 중이거나 전송 결과·요청 소유권을 확인하지 못한 경우에는 전환을 거절하고
대화 화면과 초안을 유지합니다. 창 숨김이나 연결 정리는 이 입력 인계를 대신 실행하지 않습니다.
이력을 조회하는 동안 새 이벤트가 도착하면 늦은 응답으로 최신 내용을 덮어쓰지 않고
다시 조회하도록 안내합니다. 이력 조회 불가를 빈 대화나 유휴 상태로 처리하지 않습니다.

우측 상단 **질문함**은 확인된 미응답 질문·승인 요청의 건수를 보여줍니다. 질문함을
열어도 건수는 초기화되지 않으며, 서버에서 해결됐음을 확인하면 줄어듭니다. 원문을
수집한 터미널 질문은 원래 세션에서 응답합니다. 질문 원문을
조회할 수 없는 응답 대기 상태는 별도 안내와 원래 세션으로 이동하는 기능을
제공합니다. 이 상태를 확인된 질문 수로 계산하지 않습니다.

전송한 붙여넣기 이미지는 이후 대화 재개에 필요할 수 있어 앱 소유 저장소에 보존합니다.
미전송 임시 파일은 정리하고 사용자 원본은 삭제하지 않습니다. 저장소 예산을 넘으면
이전 첨부를 자동 삭제하는 대신 새 첨부를 거부합니다.

## 세션 컨텍스트 표시와 압축

세션 상단에서 컨텍스트 사용량과 수동 압축 버튼을 확인할 수 있습니다. 표시 비율은
서버가 보고한 최근 모델 응답의 토큰 사용량을 컨텍스트 창 크기로 나눈 값입니다.
누적 과금 사용량이나 터미널 대화록 크기가 아닙니다. 아이콘에 마우스를 올리면
토큰 수를 확인하고, 클릭하면 새로고침합니다. 누락되거나 오래된 측정값은 —로 표시합니다.
보이는 세션만 2초마다 작은 로컬 상태 하나를 읽으며 숨긴 세션은 조회를 멈춥니다.

수동 압축은 같은 대화에 연결한 뒤 진행 중 작업·승인 대기·결과 미확인이 없을 때만
요청합니다. 실행 중 작업을 대체할 수 있는 기존 압축 명령으로 우회하지 않으며,
원자적으로 유휴 상태를 확인하는 기능이 없는 실행 환경에서는 압축을 제한합니다.
요청 접수와 완료를 구분하고 결과가 불명확하면 자동으로 재요청하지 않습니다.
작성 중인 초안과 원래 대화는 보존합니다.

## 세션 예약 작업

세션 상단의 시계 아이콘에서 해당 CLI가 소유한 예약 작업을 조회하고 등록·일시정지·재개·삭제하거나 현재 회차의 중단을 요청합니다. 반복 간격과 한 번 실행할 현지 시각을 선택할 수 있습니다. CLI가 종료되면 예약도 끝나며, 별도 운영체제 예약은 생성하지 않습니다.

예약 삭제와 일시정지는 이미 실행 중인 회차를 중단하지 않습니다. 현재 회차 중단은 해당 예약이 시작한 작업만 대상으로 하며 반복 예약은 유지합니다. 결과가 불명확한 요청은 자동 재전송하지 않고 처리 여부가 확인될 때까지 변경을 제한합니다. 구조화 예약 제어를 지원하지 않는 CLI에서는 미지원 안내와 함께 변경 기능을 제한합니다.
